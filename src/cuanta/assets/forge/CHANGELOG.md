## [0.4.0] - 2026-09

Teaches the skill to cooperate with **cuanta** — a CLI that runs detection and the graph bootstrap in code, drives the headless run, and accounts for every token it spends — **without changing a single thing when cuanta is absent**. Every addition below is conditional on evidence cuanta leaves on disk (`"producer": "cuanta"` in the state file, a `.cuanta/` directory, a `CUANTA_RUN_ID` variable). A repo that has never seen cuanta runs the v0.3.1 skill, with one deliberate exception: the `VERIFY_TIER=strong` rule below.

### Added
- **The cuanta handoff in Phase 0.** A `.claude/forge-state.json` written with `"producer": "cuanta"` and phases `0` and `0.5` completed is adopted as-is: the recorded variables stand, the nine-line summary is printed from them with `run: resuming from Phase 1 (handed off by cuanta)`, and the run continues at Phase 1. Detection and the graph bootstrap are never paid for twice.
- **A `Consumption:` line in the `docs/RUN_LOG.md` entry** — `run $CUANTA_RUN_ID → cuanta spectrum $CUANTA_RUN_ID` — written only when the mandate ran under cuanta, so the observability layer points at the token map of the run it records. Omitted otherwise; never a placeholder.

### Changed
- **`VERIFY_TIER=strong` no longer requires a typecheck or build step.** A test runner alone is `strong`, and the evidence records the gap verbatim — `pytest, no typecheck` — while the tester's `strong` contract tells it to say that types are unchecked. The runner is the behavior sensor the tier exists to detect; a missing typecheck is a gap to record, not a reason to withhold the loop. **This is the one change in 0.4.0 that also applies without cuanta**, so the skill and cuanta compute the same tier.
- **Phase 3's tester fill when `.cuanta/` exists.** `{{TEST_CMD}}` becomes `cuanta test --json`, and the truncation rule becomes *the gateway output is already bounded; never pipe it*. The gateway returns one line per failure signature and keeps the full log in a capsule; `| tail -n 40` on top of that can only cut the part that matters.
- **The mandate template's tester step** names the same path: `cuanta test --json` when available, and failure detail through `cuanta cat <capsule> --level L2` instead of re-running tests one by one. The standalone instruction is unchanged and still comes first.
- **Iterate on affected tests, decide on the full suite.** With cuanta, the tester runs `cuanta test --affected --json` while iterating (tests related to the changed files, last failures first) and the full `cuanta test --json` for the verdict; cuanta itself runs the full suite once more at the end of every mandate before it reports green.

## [0.3.1] - 2026-08

Closes the one thing v0.3 shipped without: a ceiling on the continuity layer. `HISTORIAS.md` and `docs/IMPROVEMENTS.md` had per-entry budgets (3 lines per story, 1 line per gap) but no bound on how many open entries could accumulate — the same monotonic-growth defect this project already fixed twice, in the rulebook and in the per-directory files, reappearing one layer up and worse, because **the analyst reads those files off-budget** and nothing else brakes it.

### Added
- **A 15-open-entry cap on both continuity files**, written into each file's own budget header so it survives independently of the skill: `HISTORIAS.md` caps `pendiente` + `en progreso` at 15; `docs/IMPROVEMENTS.md` caps unchecked entries at 15.
- **A deterministic, terminating, non-blocking overflow path**, mirroring the 300-line ceiling exactly. At the end of each cycle the docs-updater counts, then consolidates in a fixed order: **merge duplicates** (oldest ID wins, absorbed IDs recorded) → **close the stale** (90 days untouched → `descartada — stale` / `wontfix — stale`, moved to `docs/CHANGELOG_INTERNAL.md` on that same cycle) → **demote** the lowest-severity `low` items, oldest first, to a `## Deferred` section at the bottom that the analyst never reads (`en progreso` is never demoted — work in flight is not deferred behind the analyst's back). Re-count; still over → **write anyway** with `⚠ Over cap: <n>/15 open — consolidation exhausted. Oldest open: <ID, date>.` under the title. **A cap must never cause a cycle to stall, refuse, or silently drop an entry.**
- **`continuity` in the docs-updater's JSON** — open counts per file after the cycle, plus `merged`, `staled`, `deferred` and `over_cap`. Consolidation that is not visible is indistinguishable from data loss.
- **`SECURITY.md`** — `CONTRIBUTING.md` pointed at a file that did not exist. Under 30 lines and honest: no network calls (bar the opt-in graph install, which fails soft), no git operations, no execution of repo code beyond the commands the user's own manifest declares, no telemetry; latest release supported only; GitHub issues for reporting, with no invented bounty or response window.

### Changed
- **The analyst's off-budget read is now bounded** — off-budget was never meant to mean unbounded. It reads at most **15 open entries per file**, top-to-bottom, **never** a `## Deferred` section. On a repo whose docs-updater has not yet consolidated it reads the **newest 15**, sets **`continuity_overflow: true`** in the plan JSON, and **proceeds** — refusing to plan over an overflow would block work on precisely the repo that most needs it.
- **Phase 6's missing-runner seed is idempotent.** It scans the unchecked entries for one whose normalized text already says the same thing (ID, date and path tails ignored) and changes nothing if found; an entry a human demoted to `## Deferred` is not re-seeded above them. `/init-agents` on a forged repo and every `/refresh-agents` both re-enter this step, and without the guard each run stacked another copy — a file whose top three entries are the same gap teaches the reader to skim past it. At `strong`, an existing missing-runner entry is **closed** instead.
- **Both installers state the manifest rule in a comment**: adding a template is adding one line to each list, the check is by **name and never by count**, and the two lists are kept identical. The existing checks were already name-based — verified, not rewritten.

### Fixed
- **`/refresh-agents` had the Phase 6 re-run step but no reference to compare against.** It now compares the freshly computed `VERIFY_TIER` against the `verify_tier` stored in `.claude/forge-state.json` (with no stored value — a repo forged before v0.3 — treated as new and run once), states the transition (`verify: moderate → strong (jest added to devDependencies)`), and on change does all three things together: rewrite `docs/LOOP.md` to the new tier, refill the tester's `{{VERIFY_TIER_CONTRACT}}` **under the `.new.md` policy**, and — when the tier rose to `strong` — **close the missing-runner improvement** into the changelog rather than leaving a resolved gap sitting open. The current tier is written back to the state file afterward. Phase 0's writer now names `verify_tier` explicitly instead of "all five variables".
- One numeric cross-reference into `AGENTS_GUIDE.md` (`see §7`) replaced with the section's name. Every other reference in the repo was already name-based (`§Harness`) and resolves correctly after v0.3's renumbering.

## [0.3.0] - 2026-08

Closes three defects verified on the first successful v0.2.1 run, and the two structural gaps that kept the skill from working on every project it will meet: **scale** (every phase assumed the whole repo fits in one pass) and **continuity** (every mandate started from a blank page). It also names what the skill has always built — a **harness** — and adds the missing layer above it: the **loop**.

### Added
- **A fourth size tier, `xl` (≥2000 source files)**, where the strategy changes rather than the thresholds. Phase 1 **audits by sampling** — a representative sample plus the graph's high-degree nodes, with the sample size stated — because an honest partial audit beats an unfinishable complete one. Phase 2B selects directories **from the graph only** (clusters, cross-directory edge density), never by walking the tree. The per-run cap applies hard.
- **Resumable runs — `.claude/forge-state.json`.** Written after every phase and every Phase 2B batch, read at the start of Phase 0. A run that dies at Phase 3 resumes at Phase 3 and announces `resuming from Phase <n>`; a corrupt state file is discarded with a note, never a hard failure. It is bookkeeping, not knowledge, and it is added to `.gitignore` (a file edit — never a git command).
- **Batched Phase 2B.** At most **6 directories per batch**: write the files, update the state file, and **release that batch's evidence from working context before the next**. Holding every directory's evidence at once is the specific thing that makes a monorepo run fall over. **Hard cap of 20 rulebooks per run**; qualifying directories beyond it go to `dirs_queued`, are reported in the closing summary, and are drained by the next `/refresh-agents`. A queued directory is a stated outcome, not a silent omission.
- **`VERIFY_TIER`, computed in Phase 0 and printed** — `strong` (test runner **and** typecheck/build) · `moderate` (typecheck/lint/build, no runner) · `weak` (build only, or nothing verifiable). It fills the generated tester's contract: a `moderate` repo's tester states plainly that it proves compilation and lint, **never behavior**, and never reports `green`.
- **Phase 6 — the loop specification.** Writes `docs/LOOP.md` in five parts: trigger, goal, verification (the §Commands entries verbatim, each with what it can and cannot prove), stopping rule (self-verification, the tester's three-attempt cap, the one-return-trip limit, the two halt conditions — **every loop must be able to stop without a human**), and memory. **The honest gate**: an unattended sequence may be described **only** at `VERIFY_TIER=strong`; `moderate` states explicitly that no unattended loop is sanctioned because compiling is not behaving; `weak` gets one paragraph — get a sensor first. In `moderate` and `weak`, "install a test runner" is seeded automatically as the top entry in `docs/IMPROVEMENTS.md`. A skill that offers autonomy to a repo that cannot verify itself sells the exact failure mode the discipline exists to prevent; **refusing there is the feature**, and no request for more autonomy overrides it.
- **The harness, named.** `AGENTS_GUIDE.md` gains a **§Harness** section mapping each layer to the artifact that implements it: tool orchestration (the four agents + the scope gate), verification (the tester's bar, `VERIFY_TIER`), context & memory (graph / rulebook / facts file / changelog), guardrails (§Do not break, gate-OFF byte-identical, exceptionless boundaries), observability (the run log).
- **`docs/RUN_LOG.md` — the thin layer filled.** Append-only, one block per completed mandate: date, scope, phases run, files touched, tests result, recommendations raised, HU reference. Written by the docs-updater, **never auto-loaded**. It is the record you read when a mandate misbehaves and you need the trajectory.
- **`docs/IMPROVEMENTS.md` — where found gaps live.** The FINAL REPORT's recommendations were real findings that evaporated into chat scrollback; they now get one line each (`- [ ] IMP-004 — … — <path>:<line> — found <date> in <HU-NNN|init> — severity: …`), appended by the docs-updater from the tester's and senior's JSONs, **never invented to fill space**. A resolved item is checked and moved to the changelog on the next cycle, so the file stays a list of *open* gaps.
- **Four new templates**, each with its budget header and what does NOT belong in it: `RUN_LOG.template.md`, `IMPROVEMENTS.template.md`, `HISTORIAS.template.md`, `LOOP.template.md`.

### Changed
- **`HISTORIAS.md` becomes read-write — the loop's memory.** It was write-only: the run recorded a story and never read one back, so every mandate re-derived context a previous one had already paid for. Entries now have a fixed, parseable shape (`Estado` / `Contexto` / `Depende de` / `Cierre`), three lines of substance and no transcripts. **The analyst reads the OPEN entries only** (`pendiente`, `en progreso`) plus the unchecked improvement lines before planning, and returns **`related_stories`** and **`related_improvements`** in its plan JSON — the only two additions to any agent's JSON contract.
- **The mandate closes by opening the next one.** `MANDATE_TEMPLATE.md`'s FINAL REPORT gains a **NEXT** section after the commit proposal: read the open backlog and improvements, propose the single most sensible next mandate with a filled REQUEST block, recording any new story or gap first. **Propose only — never start it.** Its opening pipeline step now states that the analyst reads the backlog before planning and says whether the request continues existing work or opens new ground.
- **The docs-updater routes to seven destinations**, adding `docs/IMPROVEMENTS.md` and `docs/RUN_LOG.md` to the five it had, and writes the `HISTORIAS.md` entry in the parseable shape. Its JSON contract is unchanged: the two new writes are recorded in the existing `moved_out` array.
- **`/init-agents` is ten phases** (0, 0.5, 1, 2A, 2B, 2.5, 3, 4, 5, 6), with resumability and `FORGE_STATE` routing stated. **`/refresh-agents` drains `dirs_queued` first** and **re-runs Phase 6 when `VERIFY_TIER` changed** — installing a test runner should upgrade the loop spec, and removing one must downgrade it.
- **Both installers verify every skill file and command before copying**, failing loudly on any missing one rather than leaving a half-install that only breaks later inside the user's repo.

### Fixed
- **Phase 0.5 branch collision.** A run reported `GRAPH_MODE=cli detected → skipped (small tier)`: Branch C (graphify present → re-index) and Branch A (small → skip) were both true and the spec never said which wins, so the run improvised. Skipping was right; the silence was not. **The size gate now sits explicitly above mode detection** — `SIZE_TIER=small` wins over a present CLI or MCP server — with the precedence table written out, the tie-break sentence added to Branches C and D, and the requirement to **name the condition that won**: `skipped (small tier; graphify present but not indexed for this repo)`. Reporting only the outcome reads as a bug even when the behavior was right.
- **A second `/init-agents` treated an already-forged repo as a virgin audit.** A run reported `DOCS_STATE=partial` and "nothing was deleted as stale" because it was auditing a rulebook a previous forge run had written — the classifier grading its own homework, so nothing is ever stale and the audit path is never exercised. Phase 0 now computes **`FORGE_STATE`** (`initialized` when `.claude/agents/` holds forge-generated agents or the support artifacts exist, else `fresh`), and an `initialized` repo routes `/init-agents` to **refresh semantics**: verify against code and graph, never re-classify forge-written boilerplate, never overwrite tuned agents, and say `forge: initialized — running refresh semantics`.
- **The registration step was never said out loud.** A run hit `Error: Unknown skill` and recovered by reading `SKILL.md` off disk — a recovery a new user has no way to know exists, so the tool simply looks broken. The plugin's skill and commands are unavailable in the session that installs them; that is now in the README install steps, in both installers' final echo, and in every closing summary. A run that had to fall back reports `registration: deferred — restart the session before the next command`.
- **The 300-line ceiling could stall a run.** "Over it, the cycle's job is to move content out, not add" had no defined end when relocation ran out. The overflow path is now **deterministic and always terminating**: check → relocate in the fixed order (structure deleted, the graph owns it → narrative → the full flag registry → external derivations → single-directory rules) → re-check → **still over, write the file anyway** with `⚠ Over ceiling: <n>/300 — relocation exhausted. Split candidates: <the sections>` under the title, and report it. The same rule governs the 40-line per-directory cap. **A size rule must never cause a run to stall, refuse, or leave a repo half-written** — stated in `SKILL.md`, in `reference/claude-md-spec.md`, and in the docs-updater contract.

### Notes
- **Deliberately not built:** a scheduler, a daemon, or a webhook trigger. Phase 6 *describes* the loop; it does not automate it. Nothing runs without a human pasting a mandate.

## [0.2.1] - 2026-07

Fixes the outcome v0.2 produced on its most common path: a **SEED** run — a repo with no prior `CLAUDE.md` — finished with a graph, four agents, a root rulebook, and **no per-directory rulebooks at all**. The rule that caused it was correct and is unchanged: per-directory files hold local rules only, and local rules come from experience a new repo has not had. The defect was the missing derivation. **Architecture yields rules, and the skill now derives them.**

### Added
- **Phase 2B — write the per-directory rulebooks.** Phase 2 splits: 2A writes the root file (unchanged behavior, narrowed scope), 2B is new. It selects the directories that earn a rulebook (a cohesive graph boundary, conventions provably differing from the root's, a seam onto an external system, its own run/test command, or prior `RULE`-classified docs on the audit path), derives content from evidence only in five parts — purpose, local rules, boundaries, local commands, local gotchas — and caps each file at 40 lines. **The fix is derivation, not relaxation**: directory trees, file inventories and import lists remain the graph's, and are still never written.
- **Rejections are reported.** Phase 2B outputs the directories that were considered and skipped, each with its reason (`utils/ — skipped: shares root conventions, no boundary of its own`). Silence about a skip reads as a broken tool; that silence was the visible half of this defect.
- **Exceptionless-boundary rule.** A boundary is written only when the pattern has no counter-example in the graph. One `worker/ → api/` edge and "worker must not import api" is a tendency, not a rule — shipping it as a rule means the next agent "fixes" working code. Exceptionless or unwritten.
- **Honest empty gotchas.** On a seed run the local-gotchas section ships empty with one line inviting accumulation, rather than padded or omitted. It is where the file grows.
- **Phase 5 completion assertion.** Before the closing summary the skill now asserts all five artifact classes actually exist: graph wired or deliberately skipped with the reason recorded; four agents with **zero surviving `{{placeholders}}`, scanned not assumed**; root rulebook under 300 lines; a per-directory rulebook for every directory that qualified plus a named reason for every rejection; and the five support artifacts. Anything failing is fixed and re-verified. The summary gains a `per-directory:` line.
- **Re-run policy.** Neither command overwrites a file the user may have tuned. Phase 3 writes a differing regenerated agent to `<name>.new.md`, preserves the original, and reports both paths. Phase 2B preserves existing per-directory rulebooks on a fresh init and updates them in place only on an audit run.

### Changed
- **`docs-updater` routes local rules DOWN, in the normal path.** The scope question — *does this rule apply to exactly one directory?* — now runs **before** the root-vs-elsewhere choice, not only after the root file has already overflowed. Routing a directory-scoped rule to root is how the root reaches its ceiling and how directory files stay empty forever. Per-directory writes get their own budget (**max 3 lines per cycle per directory**, 40-line cap) and a **create-if-missing** rule using Phase 2B's five-part shape — decided from the analyst's plan JSON, without reading source or querying the graph. This is how a seeded repo's architecture fills in over the first weeks of real work. Its JSON deliverable gains `per_directory_changes` (`path`, `lines_added`, `created`).
- **`/refresh-agents` regenerates the four agents from the current templates, always** — not only when the stack or `GRAPH_MODE` changed, and under the same `.new.md` policy. A repo initialized under v0.1 carries the old docs-updater, the one with no budget whose knowledge base grows forever; without this, those users kept that defect permanently with no way to learn it. Refresh also writes any per-directory rulebook a directory has since earned.
- **`reference/claude-md-spec.md`** — the per-directory rulebook becomes the five-part shape with the structure-vs-rule table, the exceptionless-boundary rule, the 40-line cap and the never-overwrite policy. The three hard rules are unchanged; rule 3 gains one clarifying sentence — it excludes inventory files, it does not excuse skipping the phase.

### Fixed
- **Phase 4 never named `{{PROJECT_NAME}}` or `{{SENIOR_NAME}}`.** Phase 3's fill list covers them but is explicitly scoped to "the four agent templates", while four of the five Phase 4 artifacts use `{{PROJECT_NAME}}` and two use `{{SENIOR_NAME}}`. Both are now in Phase 4's fill list. A shipped `{{SENIOR_NAME}}` in `docs/MANDATE_TEMPLATE.md` makes the mandate unrunnable as pasted — exactly the defect the README names as most likely.
- **`{{SEEDED_ENTRIES}}` meant two different things.** It appeared in both `GROUND_TRUTH.template.md` (external derivations, cited, in the facts entry format) and `CHANGELOG_INTERNAL.template.md` (the narrative Phase 1 relocated), while Phase 4's instruction described only the first — so the changelog would have been seeded with ground-truth facts. The changelog's is renamed **`{{SEEDED_NARRATIVE}}`** with its own fill instruction.
- Placeholder cross-check re-run: every placeholder in `templates/` now has a fill instruction in `SKILL.md` naming it literally.

## [0.2.0] - 2026-07

Reframes the skill around one rule: **the graph owns navigation, the rulebook owns judgment, the facts file owns expensive external derivations — nothing is stored in two places.**

### Added
- **Phase 0.5 — graph bootstrap.** Wires a code graph in one non-interactive step, with four strict branches: skipped below ~100 source files (with the reason written into the rulebook), no duplication when a graph MCP server is already configured, re-index when a graph CLI is already present, install + index otherwise. **Graceful degradation**: any install failure continues the pipeline with `GRAPH_MODE=none` and grep-based navigation rules — it never aborts the run.
- `reference/graph-integration.md` — the verified graph command surface (graphify 0.9.11: package `graphifyy`, binary `graphify`, `graphify update .` for a non-interactive build from scratch) plus the knowledge-split table and the failure policy.
- **Phase 2.5 — facts file.** Generates `docs/GROUND_TRUTH.md` (or `GROUND_TRUTH_<FRAMEWORK>.md`): append-only, dated, cited. Every reading of an external source tree is paid once and cited forever. The analyst must consult it before deriving anything.
- New artifact templates, each with a header stating its budget and what does NOT belong in it: `GROUND_TRUTH.template.md`, `CHANGELOG_INTERNAL.template.md`, `FLAGS.template.md`, `MANDATE_TEMPLATE.template.md`.
- **`/refresh-agents`** — re-verifies the rulebook against code and graph, enforces the 300-line ceiling by *moving content out*, re-indexes the graph, reports drift.
- **Scope gate** written into the generated rulebook so the main session reads it every session: trivial → no agents; normal → analyst/senior/tester; complex → full pipeline.
- Section **§Proven NOT bugs** in the rulebook spec — things that look like defects and are not, each with why flagging it would be the error. Generated empty with instructions when the repo has no history of it yet.

### Changed
- **`SKILL.md` rewritten as an eight-phase pipeline** (0, 0.5, 1, 2, 2.5, 3, 4, 5), every phase with explicit inputs, actions, outputs, and failure behavior, branching on `SIZE_TIER` and `GRAPH_MODE`.
- **`reference/claude-md-spec.md` rewritten**: the 8-section structural spec becomes a 14-section *rulebook* spec, with three enforced rules stated inside the generated file — a **300-line ceiling**, **zero drifting numbers** (store the command that asks the code, never the count), and **local rules only** in per-directory files.
- **All four agent templates rewritten** with `model`/`tools` frontmatter, a mandatory JSON deliverable ("return ONLY this JSON"), an explicit git prohibition, and no progress narration or approval requests.
- **`architecture-analyst`** — two-tree navigation contract: our repo → trust the graph's edges and **never read source to confirm an edge**; external source trees → read them, but check the facts file first. Hard read budget with a `needs_scoping` exit, STOP conditions as successful outcomes, and a mandatory `blast_radius` the other agents are forbidden from re-deriving.
- **`<lang>-senior`** — consumes the plan JSON, prohibited from re-running graph queries for symbols already in `blast_radius`, returns `blocked` on a silent graph instead of falling back to an unbounded search, one phase per invocation, deviations recorded and never redesigned.
- **`tester`** — mandatory output truncation on every command (`| tail -n 40`, `-q` over `-v`), regression fixture asserting the old behavior dead, both flag directions, negative cases (the fixture that catches a new checker false-positiving on correct code), three fix attempts then `persistent_failure` with the verbatim error.
- **`docs-updater`** — replaces "update only when architecturally significant" (which shipped no budget, so every installed knowledge base grew forever) with a four-destination routing table, a **max 5 rulebook lines per cycle**, the rule-vs-story test with a worked 15-line→2-line example, and a hard rule that **over 300 lines the cycle's job is to move content OUT, not add**. Works from the three agent JSONs only.
- **`AGENTS_GUIDE.template.md` rewritten** as an operator manual, replacing the part-by-part orchestration header whose structure taught agents that part boundaries were approval points.
- **README cost advice corrected**: downgrading the senior's model was the wrong first dial — it is the only agent writing production code. The order is now scope gate → batched docs-updater → analyst tier → senior tier last.
- Both installers now copy the same file set, including `/refresh-agents`, and fail loudly on a missing command file.

## [0.1.0] - 2026-06
### Added
- Initial public release of the `agent-system-init` skill.
- `/init-agents` slash command — runs the full method autonomously (no approval gate).
- Generates a verified `CLAUDE.md` knowledge base (root + per-directory) by analyzing the repo's real architecture, design patterns, conventions, and dependencies.
- Creates the fixed 4-agent pipeline in `.claude/agents/`: `architecture-analyst` (sonnet), `<lang>-senior` (opus), `tester` (sonnet), `docs-updater` (haiku).
- Produces `AGENTS_GUIDE.md` with a copy-ready orchestration prompt template.
- Handles repos with no existing `CLAUDE.md` by inferring a base from the code and marking unverifiable items `[UNVERIFIED]`.
- Claude Code plugin packaging (`.claude-plugin/`) for one-command install via `/plugin marketplace add` + `/plugin install`.
- Manual installers: `install.sh` (macOS/Linux) and `install.ps1` (Windows).

### Notes
- Early release. Validated on real repositories (including an Odoo 17 addon project, where it surfaced a latent dependency issue) but not yet benchmarked across many stacks. Review generated output and check for any unfilled `{{placeholders}}`.
