# External contracts — cuanta

This registry records external behavior that cuanta uses or plans to use. `verified` means the stated behavior was checked on the version shown, by installed CLI output or a live capture. It does not automatically carry forward to a newer version. `unverified` means documentation or local tests exist without an installed-runtime check of the stated behavior. `broken` means an observed result or the current integration contradicts the contract. Dates mark the last evidence review, not a promise about future releases.

The M0 live probes below used Claude Code 2.1.282 with subscription authentication on 2026-09-25. The installed CLI was 2.1.283 when its help was checked later that day. Probe costs are usage estimates under a subscription, not additional API charges. No M0 probe is needed to read this file.

Read-only rechecks: `claude --version`, `claude --help`, `codex --version`, `codex exec --help`, `opencode --version`, `opencode run --help`, `graphify --version`, and `cuanta --plain doctor`. See the [Claude Code CLI reference](https://code.claude.com/docs/en/cli-reference) for flags omitted from `claude --help`.

## Updating this registry

- Before relying on a new external flag, setting, stream field, protocol revision or price, check the installed version and update the relevant row with its date and evidence.
- Record a live probe's usage estimate and its limitations. A version upgrade requires a new runtime check for behavior that help text alone cannot establish.
- Put source readings in `docs/GROUND_TRUTH.md` and product fixes for broken rows in `docs/IMPROVEMENTS.md`.
- Keep paths repository-relative and exclude credentials, personal addresses, client details, and private session identifiers.
