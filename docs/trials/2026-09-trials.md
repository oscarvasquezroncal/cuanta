# Trials, September 2026 — what an audit, a fix and a feature really cost

The first real measurement of cuanta on a production Next.js landing page (Next 16 with
Turbopack, Windows host, Claude Code 2.1.283, Codex CLI 0.156.1). Every trial ran with
`cuanta mandate --sandbox`: the agent worked in an isolated copy, and nothing was applied to the
project. Outcomes were recorded with `cuanta runs accept|reject`.

## Acceptance

Checked in fresh isolated copies with the run's changes written in; the project itself was
never touched.

- **T1b-2 — accepted.** Type check and `npm run build` pass; the build emits `/sitemap.xml` and
  `/robots.txt`, and the page has a canonical link. The canonical and sitemap URLs use the same
  base as `metadataBase`, which falls back to `http://localhost:3000` until the public site URL
  variable is set in deployment.
- **T1c — accepted.** Type check, lint and build pass. The fallback wraps the GSAP set-up in
  `try`/`catch` and sets `visibility: visible` on the revealed root when GSAP throws. Limit: if
  GSAP fails after hiding staggered children, the root shows but those children stay hidden.
- **T1e — accepted.** Build passes; valid `Organization` JSON-LD with name, url, logo and
  contact, taken from the project's own constants. The contact phone is the one the project
  already flags as a probable placeholder; confirm it before publishing.
- **T1d — rejected.** Build passes and the JSON-LD is valid, but it carries only name and url;
  the pipeline ran out of budget before the tester finished and the docs role never ran.
- **T1f — rejected.** No code change: Codex stopped because the brand data was not verified,
  recorded a blocker in two docs files, and reported that `npm` and `npx` were not available in
  its sandbox.
- **Investigations — accepted.** Each report answers its question with `file:line` evidence (6,
  15 and 12 references).

## Observations

- **Warm prefix.** The second run of each pair started warm: 69% of T1a's first request and
  66% of T1c's came from the cache. The rest (about 9k and 19k tokens) was written fresh, so part
  of the "fixed" context still changes between runs; neither pair started cold, so the
  dynamic-section flag (CC-19) was not tried.
- **Estimates.** History-based estimates landed within 17%. Plan-based estimates overshot the
  Forge pipelines about threefold (IMP-003).
- **Isolated copies.** Each copy took about 13 s (336 files copied, 33,933 dependency files
  hard-linked). The node_modules and `.cuanta` guards stayed clean in every run.
- **Session title request.** Claude Code sends a small title request before the agent's first
  request (CC-21).

## Bugs found

- **Fixed in T1:** cuanta took Claude Code's session-title request as the run's first request,
  so first-request size, fixed context, cache state and start-up timing were wrong for every
  Claude run. The first request is now the first non-auxiliary one.
- **Logged** in `docs/IMPROVEMENTS.md`: budget starvation in cross-engine pipelines (IMP-002),
  plan-based estimates too high (IMP-003), Codex without `npm`/`npx` in its sandbox (IMP-004,
  CX-09), a cross-engine run timed by its first role (IMP-005), a turn count above the limit
  (IMP-006).

## Applying the accepted changes

The accepted feature and fix are waiting in the project's `.cuanta/trials/`. The owner applies
them on the project's current branch, one commit per trial, using the commands cuanta prints
(`cuanta runs branch <id> --shell cmd`), which stage only each trial's files:

```
cd /d <project folder>
git switch <current branch>
cuanta runs apply 01M3G8JCP2K0W18HD7ADKKC5TK --yes
git --literal-pathspecs add -A --pathspec-from-file=.cuanta/trials/01M3G8JCP2K0W18HD7ADKKC5TK/paths.nul --pathspec-file-nul
git --literal-pathspecs commit -F .cuanta/trials/01M3G8JCP2K0W18HD7ADKKC5TK/commit.txt --pathspec-from-file=.cuanta/trials/01M3G8JCP2K0W18HD7ADKKC5TK/paths.nul --pathspec-file-nul
cuanta runs apply 01M3G8PDWN0YSB1BQFQ9TC3NNR --yes
git --literal-pathspecs add -A --pathspec-from-file=.cuanta/trials/01M3G8PDWN0YSB1BQFQ9TC3NNR/paths.nul --pathspec-file-nul
git --literal-pathspecs commit -F .cuanta/trials/01M3G8PDWN0YSB1BQFQ9TC3NNR/commit.txt --pathspec-from-file=.cuanta/trials/01M3G8PDWN0YSB1BQFQ9TC3NNR/paths.nul --pathspec-file-nul
```

T1b-2 and T1e both change the root layout, so after T1b-2 is applied, `cuanta runs apply` refuses
T1e because the file changed since its copy; rerun that feature on the new layout instead. The
project had many uncommitted edits during the trials; where a trial's files already had such
edits, the commit includes them, and `cuanta runs branch` lists those files first.

The T1b-2 run is the feature baseline for the V4 comparison.

## The product today

on sandbox copies of the same production Next.js landing page. Each request is configured
once for Sonnet 5 and once for Opus 5.5, at normal depth; observed deviations are below.
Audits use a single context; changes use the
pipeline. Sonnet pipelines pin every role to Sonnet; Opus pipelines pin senior and tester
to Opus and keep orchestrator, analyst and docs on Sonnet. This configuration is frozen for
V4. It describes planned roles; the native engine can complete a request without invoking
every subagent.

Attempt time comes from the recorded start/end timestamps and is comparable to T1.
Whole launch time also includes copy creation and capture. Token/turn values retain the
engine and Spectrum boundaries; a configured native pipeline is not proof that every role
ran. The Opus audit's observed model is Opus, even though Spectrum's planned-main label
incorrectly says Sonnet. That label discrepancy is retained rather than interpreted as a
model substitution.

The first change exposed a separate driver contract failure: engine-qualified pins such as
`senior=claude:claude-sonnet-5` reached native routing unchanged and did not resolve, so its
default senior ran on Opus. The mixed-mode parser handles that prefix, but native routing
expects the model reference without it. Observed models govern this report; the nominal
all-Sonnet comparison is blocked where the defaults differ. The already-started series keeps
its costs and outcomes, with no budget-reset relaunch to conceal that failure.
The driver now removes matching engine prefixes for native role references, retains them in
cross mode and rejects another engine in native mode. Serialization-through-routing
regressions cover both Sonnet and Opus. The frozen spec itself is unchanged; a corrected V4
change cannot be called a clean model-controlled comparison to a misrouted E1 row.

The Sonnet fix's external typecheck, lint and build all passed. Its two frozen source
regexes require a bare `catch {`, while the patch uses `catch (error) {`, so both checks
failed. Independently of that syntactic check, its fallback leaves staggered children
hidden when setup throws after GSAP has hidden them; the report acknowledges the gap.
The outcome is rejected, and no check was weakened to obtain acceptance.
The Opus fix restores the staggered children and clears partial inline animation styles,
but also uses `catch (error)`, so the unchanged source checks reject it. Its catch sits inside
the context callback; failure of the outer `gsap.context` call is not covered. Neither patch
has a runtime fault-injection test. External lint/build success does not establish the
requested failure behavior.
